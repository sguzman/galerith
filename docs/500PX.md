# 📸 500px guarded public single-photo preview

Pinned source: [gallery-dl 500px.py](https://github.com/mikf/gallery-dl/blob/7f226f74108501c8ac3120548370f68f19e6f9b3/gallery_dl/extractor/500px.py). **Status: partial independent Rust implementation.** Only source-backed public single-photo IDs are accepted, not the full 500px feature set.

The matcher recognizes `500px.com/photo/NUMERIC_ID[/SLUG]` and `web.500px.com` photo pages. Numeric IDs and source URLs are validated, rejecting lookalike domains, credentials, private queries, unusual ports and path traversal. The native implementation requests pinned expanded image data from `https://api.500px.com/v1/photos`, with `expanded_user_info`, tags/geo/equipment/licensing/release fields and `image_size=4096` options plus the exact source photo ID. An `Origin: https://500px.com` header is set.

The returned `photos[ID]` must match the requested photo; the highest source-provided `images[-1].url` rendition is selected only if it uses trusted HTTPS 500px media hosts. The parser bounds API JSON to **2 MiB** and image renditions to **32**, validates the image format and emits typed directory/URL messages with source-backed name, format, username, tags and optional dimensions/views. It does not invent full metadata or reinterpret the API image ordering.

URL/origin checks, expanded response mapping, hostile CDN rejection, and a real one-request loopback HTTP API fixture passed [Linux CI 40144519987](https://github.com/sguzman/galerith/actions/runs/40144519987), including formatting, Clippy, tests and release build. These are **offline fixtures**, not live 500px authentication or CDN confirmation.

**Not accepted:** full GraphQL user photo streams, user galleries and liked-photo modes, pagination/cursors, account cookies/CSRF requirements, comprehensive filename/directory/archive semantics and live pinned upstream differential parity.
